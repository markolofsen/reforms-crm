# @hub/agent

What an agent session of the hub is, for both CLIs (Claude Code and Codex), and what it may read of the admin. The design, the
two modes, the guards and the Agent tools rows are owned by `@docs/core/24-terminal.md`; this page is the package's layout.

| Export | What |
|---|---|
| `./session` | The two modes (`agent.unattended` false: the CLI asks; true: no prompts, the OS sandbox on), the protected paths, the CLI versions the guards were measured on, `CLI_LABELS` |
| `./claude`, `./codex` | One session of each CLI, built without writing: Claude's settings (P55: `model`, and `advisorModel` or the advisor's off switch, from the project's agent settings; `ADVISOR_RULE`, the advisor's rule line), strict MCP file and deny rules; Codex's own home `state/codex/<slug>/` (`config.toml`, `rules/hub.rules`, `skills/` links, `auth.json` link). `hub agent` (`apps/installer/src/agent.ts`) writes them |
| `./deny` | What no session may use in any mode: send-like tools (`SEND_LIKE_TOOL`, draft tools excepted), `hub send`, the owner-only sequence commands, the local API by address, other projects' folders and (P76, `otherDrops`) other projects' and the Shell's drop folders under `state/drops/`; the hub's MCP servers (`HUB_MCP_SERVERS`). A belt beside the sandbox, not the boundary |
| `./checks` | `agentChecks(...)`: the Agent tools rows per project and CLI, each red row with one fix line; rows 1 and 2 come from `./detect`. One source for `hub doctor --only Agent` and Settings ▸ Agent (P70). P82: the Notion row `notion.signin` (`src/notion-signin.ts`) reads what the CLI knows, never a call of the hub's own: the caller passes the project's session log (`notionEvidenceOf`, this package imports no `@hub/log`), Codex's own `codex mcp list --json` |
| `./detect` | `detectClis()`: path, version and sign-in of Claude Code and Codex in ONE login-shell spawn; `pickPreset()` (what the terminal starts by itself, P57), `cliDetector()` (the server's cache), `INSTALL_LINE` and `LOGIN_LINE` |
| `./focus` | `src/focus/` (P72, decision 0038): `readFocus` (`read.ts`), the one reader of the shared focus (`state/focus.json`, `schema: 2`: the route id and title and refs), resolved in the database opened read-only and scoped to the bound project by one resolver per ref kind (`resolvers/`: draft, client, run, knowledge, project; `RESOLVERS`, `resolveRef`): each item's title, status and the tool that reads it; `fresh`, `stale`, `elsewhere`, `none`; `depth: "line"` for the hook. `focusLine` (`line.ts`, at most 400 characters). The pointer file (`pointer.ts`: `writePointer`, `livePointer`, `readPointerFile`; `state/pointer.json`, refs only, 30 s). `hub focus --hook`, the `focus` tool and the server's `GET /api/pointer` use them |
| `./mcp`, `./mcp-stdio` | `hub mcp`: the hub's stdio MCP server for `HUB_PROJECT`: read-only `focus`, `highlight` (P72: a 30 s ring on up to 5 rows of the owner's admin, refused unless the focus is fresh; writes only `state/pointer.json` and bumps the live topic `pointer`; never clicks, types or navigates), `draft_show`, `client_show`, `drafts_list`, `mail_brand`, `project_notion` (P82: the project's Notion databases by id), `messenger_history` (database opened read-only, never a draft body), `messenger_draft_write` (P71, the one messenger write, below) and `draft_write`, the one Mail write (P52; a revision names only the hub draft and bumps the live topic `mail`, P53; every version it saves is recorded in `mail_versions` on a short write connection, a new reply to a message the project already answers is refused `already_drafted`, and a text ending with the agent's own closing is refused `own_signoff`, P65) |
| `src/messenger/` (through `./mcp`) | P71 M2 and M2b: `messenger_history` (one linked chat, or a client's linked chats: the messages newest first, the chat's rules, `owner_instruction` apart from the client's text, the open draft and `can_draft`) and `messenger_draft_write` (ONE unsent row in `messenger_drafts` on `withRepos`'s short write connection, or a revision of the chat's open draft). Linked chats only: unlinked or another project's chat is `not_linked`, named nowhere; empty text `empty_text`. `rules.ts` (`draftVerdict`, pure) enforces the chat's rules in code: `reply_off`, `no_inbound` (never first contact), `not_requested` (an `on_request` chat without the owner's words as `owner_request`), `no_nudge`, `too_soon`; an open draft is `already_drafted`. Through `@hub/db` only: no `@hub/messengers` import, so `hub mcp` loads no Telegram client. No send tool |
| `./mail-drafts` | The draft writer behind `draft_write` (P52, decision 0030): an unsent reply saved in Mail's Drafts through Mail's scripting, no window, no focus, no paste; it writes the reply text only (no hub line, decision 0031), finds its draft as a new draft of the thread in any of the project's accounts (Mail saves it in its From's account) whose text starts with the written text, and returns its Message-ID, its account and the text read back (`versionHash`); a revision moves to Trash only the older versions the caller names from `mail_versions`, each in its own account, re-checked by account and Message-ID just before the delete, and this run's own extras (a second save, Mail's reply shell); a draft not seen within 45 s is `mail_slow` (P65 S5); `writeRecorded` records each write first (`mail_writes`) and `lateSaves` finds the Hub's late saves by hash; `findInbound` finds the answered message by Message-ID (read-only). No send |
| `./write-record` | P65 S5: the write record (`writeLogOf`) and the adoption of late saves (`recordAdoptions`) over any write handle: `hub mcp`'s short connections and the server's repositories |
| `./session-rules` | `sessionRules(slug)`: the text appended to every session's system prompt; the core `AGENTS.md` section of the same heading must equal it (`apps/installer/test/docs.test.ts`); `capabilitiesOf()` (P62), the capabilities line after the identity |
| `./connectors` | P62: the connector kinds (Google-hosted Calendar and Drive, `gcal-<label>`, `gdrive-<label>`), their allowlists and hold writers, the instance's connectors, `state/connectors.json` (the account, stated or read), `resolveConnectors()` (what a project's Claude session gets; Codex none), `connectorDeniedTools()` and `sessionCapabilities()` (`@docs/core/26-capabilities.md`) |
| `./connector-guard` | P62: the guard's connector rules, blocking in every mode (off the allowlist, a hold with guests, a Meet link or a notification, another calendar, a search outside `drive.folder`), and the post hook's account read (`list_calendars`). P82 (`src/notion-scope.ts`, exported from here): `notionScopeOf` (one parse of `## Notion databases` for the capabilities line, `project_notion` and the guard), `notionViolations` (another project's database, a `database_id` parent, an update of a page not read from the project's databases: refused in every mode; no list, no check) and `notionNote` (the post hook's note on an unscoped search or a fetch from another database) |
| `./connector-checks` | P62: the connector rows of Agent tools (attached, answers, account, writes off; unattached, Codex and claude.ai connectors as info) |

Imported by `apps/installer` and `apps/server`, never by the admin. Depends on `@hub/config`, `@hub/contract`, `@hub/db` and `@hub/projects` (a project's Mail accounts for `draft_write`).
Tests: `pnpm --filter @hub/agent test` (`test/checks.test.ts`, `test/claude-model.test.ts` (also pins `--chrome` and that no Chrome tool is denied, decision 0040), `test/connectors.test.ts`, `test/drops.test.ts`, `test/detect.test.ts`, `test/focus.test.ts`, `test/mail-drafts.test.ts`, `test/messenger-tools.test.ts`, `test/notion-scope.test.ts`).

Update this page when the architecture changes.
