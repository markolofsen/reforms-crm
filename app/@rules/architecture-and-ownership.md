# Architecture and ownership

Scope: how `app/apps/admin` (Next.js 16 App Router on Turbopack, React 19, coss on Base UI, a Hono API over `/api` (types from `@hub/contract`), TanStack Query, English only) is cut into layers, and the config that holds the cut in place. Adapted from the shared "architecture and ownership" page; decision a decision or plan record kept in the owner's instance is the reason for the shape (it replaced the Vite app of 0014).

## Rules

1. MUST: one owner per concern. A route name and its path (`routes/meta.ts`, `routes/paths.ts`), a storage key, a query key, a status vocabulary, a label map each has exactly one definition; every other file imports it.
2. MUST: the layers are `app/` (route files only, thin), `routes/` (pure data and types: every destination, search schema, section; no React), `lib/` (typed edges: api, storage, clock, format, external), `hooks/` (read and move: route, project, go, search state, keys), `components/` (shared UI; `components/ui` is coss; `app-link.tsx` is the one internal link), `features/<job>/` (one screen job each). Imports go downward only: `app/` imports `features`, `components`, `routes`; a feature may import `routes`, `hooks`, `components` and `lib`; `routes` imports only `@hub/config`, `@hub/contract` and itself; `hooks` import `routes` and `lib`; `lib` imports no component; no feature imports another feature's internals. A module that must run only on the server would live in `lib/server/` with `import "server-only"` and be imported only from `app/`; none exists, and adding one needs a written reason (rule 3).
3. MUST: the Next app is a client of the Hono API and nothing else (decision 0015 section 4). The browser calls `/api/...` on its own origin; `next.config.ts` rewrites it to the server on loopback. The app imports no `@hub/db`, `@hub/mail`, `@hub/notion`, `@hub/send`, `@hub/messengers` or `@hub/projects`, and no Server Action (`"use server"`) exists: every write is a typed `fetch` from `lib/api/*` whose replies are parsed with the `@hub/contract` schemas. The server contract is the type `@hub/server` exports, imported as `import type` only; a value import would bundle Hono and SQLite into the page. Reversal needs a new decision, not a drift.
4. MUST: wire shape and domain shape are different. Parse at the one boundary (`read(schema, call)` in `lib/api/client.ts`, with a `@hub/contract` schema); a screen never invents a response shape by hand.
5. MUST: there is one alias, `@/*` to `./src/*`, declared once in `apps/admin/tsconfig.json` `paths`. Next and `tsc` read it there, Vitest through `resolve.tsconfigPaths: true`; no bundler or test config declares an `alias`. Siblings import relatively; no `../../..` chains.
6. MUST: two tsconfigs. `tsconfig.json` is the app (`src`, `test`, `next-env.d.ts`, the generated `.next/types`, the `next` plugin; `.next/dev` is excluded: a leftover dev types folder failed `next build`); `tsconfig.node.json` covers `next.config.ts`, the Vitest, Playwright and ESLint configs, `e2e` and the unit tests, with `types: ["node"]`. `pnpm typecheck` runs `next typegen` first (typed routes and `PageProps` come from it), then both. Node-only code stays out of `src` except `src/proxy.ts`.
7. MUST: the stricter tsc flags in `tsconfig.json` stay on: `verbatimModuleSyntax`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, on top of `strict` and `noUncheckedIndexedAccess` from `@hub/config`.
8. MUST: `next.config.ts` keeps what the app depends on, each with its reason in a comment: `typedRoutes: true` (the path half of `paths.ts` is checked by the framework); `agentRules: false` (Next would write an `AGENTS.md` on every start; the rules are `app/@rules`); `transpilePackages: ["@hub/contract", "@hub/config"]` (they export TypeScript source); `allowedDevOrigins` (loopback names only); `experimental.proxyTimeout: 120_000` (the `/api` rewrite answers a 500 "socket hang up" at 30 s, and the slowest call, Notion plus mail, takes about 40 s); the `/api/:path*` rewrite to `http://127.0.0.1:${HUB_PORT ?? SERVER_PORT}`; `distDir` from `HUB_NEXT_DIST` (the e2e build never collides with a running dev server); `turbopack.root` from `HUB_NEXT_ROOT`, set only by the live-edit worktree (`live-edit.md`), because Turbopack follows the symlinked `node_modules` only when its root is a common ancestor of the worktree and the main checkout. No `output` (neither `export` nor `standalone`), no `webpack` key (it makes `next build` fail), no `cacheComponents`, no `reactCompiler`.
9. MUST: the root layout (`src/app/layout.tsx`) exports `dynamic = "force-dynamic"`, owns the one theme script (blocking, inline, with `suppressHydrationWarning` on `<html>`) and mounts `Providers` (TanStack Query). Without `force-dynamic` a page that reads no dynamic API is prerendered at build and bakes in the build machine's data, and `/_not-found` fails to build. API replies live only in the Query cache; nothing caches them in Next.
10. MUST: server components are the route files, layouts and metadata, and stay thin; everything interactive is a client component, with `"use client"` at the `features/<job>/section.tsx` seam (or at a hook or component that needs it) so its children need no directive. A client component never imports a server-only module.
11. MUST: `src/proxy.ts` (Next 16's name for middleware; Node runtime) refuses, with 403, any request whose `Host` hostname is not in `ALLOWED_HOSTNAMES` of `@hub/config` and any mutating request whose `Origin` is not loopback, in front of the pages AND the `/api` rewrite (Next sets the upstream `Host` to the destination, so Hono alone never sees a foreign Host). The Hono guard stays as the second layer; both read one list. The file must be `src/proxy.ts` because `src/app` exists: at the app root Next ignores it silently.
12. MUST: the admin listens on loopback only. `next dev` and `next start` always carry `-H 127.0.0.1` (without it Next binds the wildcard address and the app is reachable from the LAN) and read the port from a variable: `HUB_ADMIN_PORT` (default 5173, the `ADMIN_PORT` constant of `@hub/config`; the live-edit loop uses 5273). `hub up` starts the production build (`pnpm start`: turbo replays `next build` from its cache when nothing changed, then `next start`), `hub doctor` checks the listener (step `admin.loopback`). The build task hashes `HUB_PORT`, `HUB_NEXT_DIST` and `HUB_NEXT_ROOT` and the `contract` and `config` packages, so a cached build is never replayed for another API port or after a type change. `HUB_PORT` is the API's port, `HUB_NEXT_DIST` and `HUB_NEXT_ROOT` are the two above. Turbo's environment is an allow-list: a new variable the app reads is added to `globalPassThroughEnv` in `app/turbo.json` in the same change, or it arrives undefined.
13. MUST: no secret reaches the browser or the app: no `NEXT_PUBLIC_*` variable, no `.env*` file in `app/` or in the app, nothing under the admin reads `state/secrets`. Logins and tokens stay in the git-ignored `state/secrets/`, read only by the server and the CLI.
14. SHOULD: a new dependency is admitted by a written reason (what it replaces, why coss, Next or the platform cannot do it). Every dependency is an exact pin (no `^`). `next` and `eslint-config-next` move together, on purpose, in a commit of their own and never inside a feature change; the target is the newest release at least 14 days old. One `cn` (`lib/utils.ts`); no second `clsx` or `tailwind-merge` user.
15. SHOULD: if UI moves into `packages/ui`, add the Tailwind `@source` line for it and list the package in `transpilePackages` in the same change, then check a production build, since dev generates on demand.
