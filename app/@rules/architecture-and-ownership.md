# Architecture and ownership

Scope: how `app/apps/admin` (Next.js 16 App Router on Turbopack, React 19, coss on Base UI, a Hono API over `/api` (types from `@hub/contract`), TanStack Query, English only) is cut into layers, and the config that holds the cut in place. Adapted from the shared "architecture and ownership" page; decision 0015 is the reason for the shape (it replaced the Vite app of 0014).

## Rules

1. MUST: one owner per concern. A route name and its path (`routes/meta.ts`, `routes/paths.ts`), a storage key, a query key, a status vocabulary, a label map each has exactly one definition; every other file imports it.
2. MUST: the layers are `app/` (route files only, thin), `routes/` (pure data and types: every destination, search schema, section; no React), `lib/` (typed edges: api, storage, clock, format, external), `hooks/` (read and move: route, project, go, search state, keys), `components/` (app-level shared UI: the pieces that know a route, a hook or the API; `app-link.tsx` is the one internal link), `features/<job>/` (one screen job each). Imports go downward only: `app/` imports `features`, `components`, `routes`; a feature may import `routes`, `hooks`, `components` and `lib`; `routes` imports only `@hub/config`, `@hub/contract` and itself; `hooks` import `routes` and `lib`; `lib` imports no component; no feature imports another feature's internals. `@hub/ui` (`app/packages/ui`: the coss copies, the product primitives, `cn`, the tokens) is below all of them: an app imports it, it imports no app, no other `@hub/*` package and no `next/*` or `@/` module. A component moves into `@hub/ui` when it imports nothing from `@/`; the moment it needs a route, a hook or the API, it is app-level and stays in the app. A module that must run only on the server would live in `lib/server/` with `import "server-only"` and be imported only from `app/`; none exists, and adding one needs a written reason (rule 3).
3. MUST: the Next app is a client of the Hono API and nothing else (decision 0015 section 4). The browser calls `/api/...` on its own origin; `next.config.ts` rewrites it to the server on loopback. The app imports no `@hub/db`, `@hub/notion`, `@hub/send`, `@hub/messengers`, `@hub/projects`, `@hub/sequences`, `@hub/terminal` or `@hub/agent` (the last two are Node only: the PTY, its socket and the agent checks; the admin reaches them through `/api` and the terminal's socket), and no Server Action (`"use server"`) exists: every write is a typed `fetch` from `lib/api/*` whose replies are parsed with the `@hub/contract` schemas. The server contract is the type `@hub/server` exports, imported as `import type` only; a value import would bundle Hono and SQLite into the page. No `dangerouslySetInnerHTML` exists in the admin or in `@hub/ui` (P49 S8): with the terminal, a script injected into a page is a shell on the owner's Mac, so mail-derived text is rendered as text only. Reversal needs a new decision, not a drift.
4. MUST: wire shape and domain shape are different. Parse at the one boundary (`read(schema, call)` in `lib/api/client.ts`, with a `@hub/contract` schema); a screen never invents a response shape by hand.
5. MUST: there is one alias, `@/*` to `./src/*`, declared once in `apps/admin/tsconfig.json` `paths`. Next and `tsc` read it there, Vitest through `resolve.tsconfigPaths: true`; no bundler or test config declares an `alias`. Siblings import relatively; no `../../..` chains.
6. MUST: two tsconfigs. `tsconfig.json` is the app (`src`, `test`, `next-env.d.ts`, the generated `.next/types`, the `next` plugin; `.next/dev` is excluded: a leftover dev types folder failed `next build`); `tsconfig.node.json` covers `next.config.ts`, the Vitest, Playwright and ESLint configs, `e2e` and the unit tests, with `types: ["node"]`. `pnpm typecheck` runs `next typegen` first (typed routes and `PageProps` come from it), then both. Node-only code stays out of `src` except `src/proxy.ts`.
7. MUST: the stricter tsc flags in `tsconfig.json` stay on: `verbatimModuleSyntax`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, on top of `strict` and `noUncheckedIndexedAccess` from `@hub/config`.
8. MUST: `next.config.ts` keeps what the app depends on, each with its reason in a comment: `typedRoutes: true` (the path half of `paths.ts` is checked by the framework); `agentRules: false` (Next would write an `AGENTS.md` on every start; the rules are `app/@rules`); `transpilePackages: ["@hub/contract", "@hub/config", "@hub/ui"]` (they export TypeScript source); `allowedDevOrigins` (loopback names only); `experimental.proxyTimeout: 120_000` (the `/api` rewrite answers a 500 "socket hang up" at 30 s; a call that waits on Apple Mail or on a provider's Test must not be cut there); the `/api/:path*` rewrite to `http://127.0.0.1:${HUB_PORT ?? SERVER_PORT}`; `distDir` from `HUB_NEXT_DIST` (the e2e build never collides with a running dev server); `turbopack.root` from `HUB_NEXT_ROOT`, set only by the live-edit worktree (`live-edit.md`), because Turbopack follows the symlinked `node_modules` only when its root is a common ancestor of the worktree and the main checkout. No `output` (neither `export` nor `standalone`), no `webpack` key (it makes `next build` fail), no `cacheComponents`, no `reactCompiler`.
9. MUST: the root layout (`src/app/layout.tsx`) exports `dynamic = "force-dynamic"`, mounts the `ThemeProvider` of `@hub/ui/product/theme` (its injected script sets the theme class before paint, so `<html>` carries `suppressHydrationWarning`; the layout writes no theme script of its own: `design-system-and-tokens.md` rule 10) and mounts `Providers` (TanStack Query). Without `force-dynamic` a page that reads no dynamic API is prerendered at build and bakes in the build machine's data, and `/_not-found` fails to build. API replies live only in the Query cache; nothing caches them in Next.
10. MUST: server components are the route files, layouts and metadata, and stay thin; everything interactive is a client component, with `"use client"` at the `features/<job>/section.tsx` seam (or at a hook or component that needs it) so its children need no directive. A client component never imports a server-only module.
11. MUST: `src/proxy.ts` (Next 16's name for middleware; Node runtime) refuses, with 403, any request whose `Host` hostname is not in `ALLOWED_HOSTNAMES` of `@hub/config` and any mutating request whose `Origin` is not loopback, in front of the pages AND the `/api` rewrite (Next sets the upstream `Host` to the destination, so Hono alone never sees a foreign Host). The Hono guard stays as the second layer; both read one list. The file must be `src/proxy.ts` because `src/app` exists: at the app root Next ignores it silently.
12. MUST: the admin listens on loopback only. `next dev` and `next start` always carry `-H 127.0.0.1` (without it Next binds the wildcard address and the app is reachable from the LAN) and read the port from a variable: `HUB_ADMIN_PORT` (default 5173, the `ADMIN_PORT` constant of `@hub/config`; the live-edit loop uses 5273). `hub up` starts the production build (`pnpm start`: turbo replays `next build` from its cache when nothing changed, then `next start`), `hub doctor` checks the listener (step `admin.loopback`). The build task hashes `HUB_PORT`, `HUB_NEXT_DIST` and `HUB_NEXT_ROOT` and the `contract`, `config` and `ui` packages, so a cached build is never replayed for another API port or after a type change. `HUB_PORT` is the API's port, `HUB_NEXT_DIST` and `HUB_NEXT_ROOT` are the two above. Turbo's environment is an allow-list: a new variable the app reads is added to `globalPassThroughEnv` in `app/turbo.json` in the same change, or it arrives undefined.
13. MUST: no secret is held or shown by the browser or the app: no `NEXT_PUBLIC_*` variable, no `.env*` file in `app/` or in the app, nothing under the admin reads `state/secrets`. Logins and tokens stay in the git-ignored `state/secrets/`, read only by the server and the CLI. One direction is open, on purpose (decision 0020): the Connections panel may SEND a Notion or Telegram token to the server for storage (`PUT /api/connections/:id/secret`), from a `type="password"` field whose value lives only in that form's state; no reply, log line, error, URL, storage or Query cache ever holds one, and nothing reads a key back. Mail has no key in the Hub (decision 0026): its rows are read-only.
14. SHOULD: a new dependency is admitted by a written reason (what it replaces, why coss, Next or the platform cannot do it). Every dependency is an exact pin (no `^`). Admitted with their reason: `next-themes` 0.4.6 in `@hub/ui` (the theme provider and its no-flash script; `@djangocfg/ui-core/theme` wraps the same library, but its install brings about 40 Radix and form dependencies and renders with its own tokens, a second token set beside coss); `@xterm/xterm` 6.0.0 with `@xterm/addon-fit` 0.11.0, `@xterm/addon-unicode11` 0.9.0 and `@xterm/addon-web-links` 0.12.0 in `@hub/ui` (P49: the embedded terminal needs a VT emulator, which neither the platform, Next nor coss has; xterm.js is the one VS Code ships, the addons fit the grid to its box, give emoji and CJK the widths Claude Code draws with, and hand links to the app; the DOM renderer, no `addon-webgl`). `node-pty` and `ws` are the server's (`@hub/terminal`), never the admin's: their reasons are in `@docs/core/24-terminal.md`. `next` and `eslint-config-next` move together, on purpose, in a commit of their own and never inside a feature change; the target is the newest release at least 14 days old. One `cn` (`@hub/ui/cn`); no second `clsx` or `tailwind-merge` user.
15. MUST: UI shared by apps lives in the one package `@hub/ui`, exported by subpath and never through a barrel: `@hub/ui/button`, `@hub/ui/table` (coss copies), the hand-written `@hub/ui/product/action-button`, `product/page`, `product/list-detail`, `product/data-table`, `product/brand-header`, `product/theme`, `product/terminal` and `product/side-dock` (the last two a folder each, with their pure helpers, exported by name), and `@hub/ui/cn`, `@hub/ui/use-media-query`, `@hub/ui/sound` (P59: `useSound`, the three synthesised tones of the agent feed; a folder `src/sound/` with its pure player), `@hub/ui/styles.css`. An app imports the stylesheet once (`apps/admin/src/index.css`: Tailwind first, then `styles.css`, whose `@source` makes Tailwind scan the package), lists the package in `transpilePackages` and in the turbo build inputs, and checks a production build, since dev generates on demand.

16. MUST: live panels (P50, decision 0028) are SQLite triggers, a tailer and one same-origin SSE route, nothing else: no broker, no generated client, no WebSocket for them. Every table in `packages/db/src/schema.ts` has three `live_*` triggers (insert, update, delete) in a migration, writing `live_seq` and `live_versions` in the writer's transaction; state that is not a row is bumped with `bumpTopic` from the server (a `LiveWatch`: one signature for the instance, or one per project, as the agent session log's `agent-log`, P59). `apps/server/src/live.ts` maps every table to a topic (`Record<LiveTable, LiveTopic>`) and serves `GET /api/live` through the `/api` rewrite with `Cache-Control: no-cache, no-transform` (without `no-transform` Next gzips and holds the stream), a ping every 15 s (under `proxyTimeout`), and at most 16 streams. The route reads only and sets no CORS header. If the rewrite ever buffers the stream, the fallback is the same frames over a WebSocket behind the terminal's guards (exact Origin, single-use ticket), changing only `lib/cache/live.ts` and `routes/live.ts`.

17. MUST: the shared focus (P51, decision 0029) has one door, one file and one reader. The admin posts it to `POST /api/focus` (`apps/server/src/routes/focus.ts`, the send ticket's guards); the server keeps the last one in `state/focus.json` (`hubPaths().focus`, ids only); `readFocus` in `@hub/agent/focus` is the only reader, behind the prompt hook (`hub focus --hook`) and the `hub mcp` server (`@hub/agent/mcp`, database opened with `openDbReadOnly`; five read-only tools, `mail_brand` among them (P60: the brand of pasted headers, no Mail read); its one Mail write is `draft_write`, P52: an unsent draft through `@hub/agent/mail-drafts`, signed by the writer with the brand's signature, never a send; a revision of a hub draft is recorded in place on a separate short write connection, like the live counter). The agent never writes the focus and the server serves no GET for it.
