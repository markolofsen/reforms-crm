# Routes and URL state

Scope: navigation in the Next.js admin (App Router): real paths with the project in the query (`/drafts/42?project=lisbon&filter=ready`). Local page: it began as an adapted copy of the shared "declarative routes" page and describes this app's own layer (decisions a decision or plan record kept in the owner's instance for the idea, `0015` for Next).

The layer, in one picture: `src/app/` holds only the files Next names (`page.tsx`, `layout.tsx`, `not-found.tsx`, `error.tsx`) and each page renders one client `features/<job>/section.tsx`; `src/routes/` (pure data and types: `search.ts`, `paths.ts`, `typed.ts`, `resolve.ts`, `meta.ts`, `sections.ts`, `guards.ts`) declares every destination; `src/hooks/` (`use-route`, `use-project`, `use-go`, `use-search-state`, `use-section-nav`, `use-hotkeys`) read and move; `components/app-link.tsx` is the one internal link; `lib/external.ts` opens `mailto:`; `src/proxy.ts` runs before every request.

## Rules

1. MUST: `src/routes/paths.ts` is the only producer of a destination (`paths.drafts.item(42, { filter: "hold" })`, a `Dest`). A path or address string literal outside `src/routes/` is a defect; the builders take typed arguments, so a wrong name or value fails `tsc` (`test/paths.types.tsx`). The path half goes through `route()` in `routes/typed.ts`, so `typedRoutes` checks it against the file tree: a page that does not exist fails `next typegen`, `tsc` and `next build`.
2. MUST: the only internal link is `AppLink`. It takes a `Dest` (`to={paths.drafts.item(id)}`), never a string and never a framework `UrlObject` (typed routes do not check one: P32 N0), and renders a real `<a href="/drafts/42?project=x">`. A plain click moves through the framework router (the shell stays mounted); a modified click, another target and open-in-new-tab are the browser's. Code moves with `useGo()` (`go(paths.…)`, `{ replace: true }` for a filter), never `router.push("/…")` with a string.
3. MUST: `next/link`, `next/navigation` and `next/router` are imported only by `src/app/**`, `src/hooks/**` and `src/components/app-link.tsx`. `routeOf()` in `routes/typed.ts` is the one door from an address text to a `Route` for `router.push/replace`: it refuses anything that is not a page of the tree (an external or `//host` address included). No `"use server"` file: navigation and writes never go through a Server Action (decision 0015).
4. MUST: only two modules touch the address bar: `hooks/use-search-state.ts` (`window.history.replaceState`, shallow: no server round trip, the framework router follows it; `router.replace` there made five RSC requests, P32 N0) and `lib/external.ts` (`location.href = "mailto:…"`). `lib/storage.ts` owns `document.cookie` for the project. Anything else that names `window.location`, `history` or `document.cookie` is a defect.
5. MUST: the URL is the state of a screen. Subject = path (`/drafts/42`, `/bulk/3`), filter, query text and the opened run = query (`?filter=hold`, `?q=…`, `?run=3`); a new batch is `/bulk?new=1`. A component keeps no second copy that Back, reload and a shared link cannot restore. Ephemeral UI (an expanded row) may stay local.
6. MUST: an unknown path is a real 404 (`not-found.tsx`); a non-numeric or zero id (`/drafts/abc`) and an extra segment render the explicit Not found state with a link to Drafts, never another screen. A bad id is streamed: its HTTP status is 200 with the Not found body and title (`notFound()` after streaming starts cannot change the status, research 19 section 5), so a test asserts the visible state and the title, never a status code for it. There is no `/clients` alias; `REDIRECTS` in `guards.ts` is empty and an entry needs a reason and a removal condition. The old hash addresses are gone, with no shim.
7. MUST: a row or card that navigates is an `AppLink` with a real `href`, not an `onClick` that sets the address.
8. MUST: search is parsed once, in `routes/search.ts` (plain functions over the enums of `@hub/config`, the same ones the API validates; a value outside its enum resets to the default). `URLSearchParams`, `params.get(` and `.searchParams` stay out of `features/`, `components/` and `hooks/`; the live query is read by `hooks/use-route.ts` and `hooks/use-project.ts` only (`useSearchParams`), and a page file reads `await props.searchParams` for its metadata.
9. MUST: a filter REPLACES the history entry (`useSearchState`), a subject PUSHES (`go(paths.drafts.item(id))`), so Back goes from a detail to its list and never steps through chips. The default value drops its key from the address.
10. MUST: the address always names the project (`?project=`). Two layers hold it, because a layout never receives `searchParams` in Next 16: `src/proxy.ts` redirects a bare project-scoped path (`PROJECT_SCOPED` in `guards.ts`) to `?project=<hub_project cookie>`; `useEnsureProject` (`hooks/use-project.ts`, in the shell frame) validates the slug against the registry and rewrites a missing, dead or non-canonical address with `replace`. The cookie `hub_project` is the remembered project, written through `lib/storage.ts`. Two exemptions, written here (`PROJECTLESS` in `routes/paths.ts`): `/overview` is about every project, so its address carries no `project` (its only search is `focus=<slug>`); `/connections` is about the instance (its logins and tokens), so it carries no `project` and no search at all. For both, `formatDest` never adds a project and the guard strips one it is given. `/` is the entry and is decided client side (`useEntry`: Overview with two or more projects or anything to attend to, else Drafts). No other route may be exempt without a sentence here.
11. MUST: the title comes from the route: each page file exports `generateMetadata` reading `pageTitle()` over `ROUTE_META` (`routes/meta.ts`); the breadcrumb reads the same table. Nothing writes `document.title`.
12. MUST: keys that navigate are derived from `SECTIONS` (`g o`, `g d`, `g b`, `g a`, `g p`) by `use-section-nav`; no key handler names a path. All key maps go through `use-hotkeys` (typing guard, modifier guard, remembered off switch).
13. MUST: the skip link is an anchor whose click handler focuses `#main` and prevents the default: a plain `#main` fragment would add a history entry and a hash to the address.
14. MUST: `src/routes/` imports no React, component, feature or hook, and no navigation library (`import type { Route } from "next"` is the one allowed `next` import). `next/*` navigation is for the modules in rule 3.
15. MUST: a page file is thin (at most 40 lines): await the params, give the title, render one feature. A new page is one change to all of: the folder under `src/app/(shell)/`, a `Dest` builder in `paths.ts`, `ROUTE_META`, `SECTIONS` when it is a section, `PROJECT_SCOPED` and the `PAGE` pattern in `typed.ts`; `test/route-files.test.ts` fails when the file tree and these disagree.
16. SHOULD: a new link, param or key uses `paths.*`, `useSearchState` and `SECTIONS`; it never adds a literal. Path routing is the design; do not add a second router or a `#/` form.
