# Routes and URL state

Scope: navigation in the Next.js admin (App Router): real paths, the project in the path when the instance has more than one (`/lisbon/drafts/42?filter=ready`) and no project at all when it has one (`/drafts/42`). Local page: it began as an adapted copy of the shared "declarative routes" page and describes this app's own layer (decisions `0014` for the idea, `0015` for Next).

The layer, in one picture: `src/app/` holds only the files Next names (`page.tsx`, `layout.tsx`, `not-found.tsx`, `error.tsx`) and each page renders one client `features/<job>/section.tsx`; `src/routes/` (pure data and types: `table.ts`, `search.ts`, `paths.ts`, `typed.ts`, `resolve.ts`, `meta.ts`, `sections.ts`, `guards.ts`) declares every destination; `src/hooks/` (`use-route`, `use-project`, `use-go`, `use-search-state`, `use-section-nav`, `use-hotkeys`) read and move; `components/app-link.tsx` is the one internal link; `lib/external.ts` opens `mailto:`; `src/proxy.ts` runs before every request.

## Rules

1. MUST: `src/routes/paths.ts` is the only producer of a destination (`paths.drafts.item(42, { filter: "hold" })`, a `Dest`). A path or address string literal outside `src/routes/` is a defect; the builders take typed arguments, so a wrong name or value fails `tsc` (`test/paths.types.tsx`). The path half goes through `route()` in `routes/typed.ts`, so `typedRoutes` checks it against the file tree: a page that does not exist fails `next typegen`, `tsc` and `next build`.
2. MUST: the only internal link is `AppLink`. It takes a `Dest` (`to={paths.drafts.item(id)}`), never a string and never a framework `UrlObject` (typed routes do not check one: P32 N0), and renders a real `<a href="/lisbon/drafts/42">`. A plain click moves through the framework router (the shell stays mounted); a modified click, another target and open-in-new-tab are the browser's. Code moves with `useGo()` (`go(paths.…)`, `{ replace: true }` for a filter), never `router.push("/…")` with a string.
3. MUST: `next/link`, `next/navigation` and `next/router` are imported only by `src/app/**`, `src/hooks/**` and `src/components/app-link.tsx`. `routeOf()` in `routes/typed.ts` is the one door from an address text to a `Route` for `router.push/replace`: it refuses anything that is not a page of the tree (an external or `//host` address included). No `"use server"` file: navigation and writes never go through a Server Action (decision 0015).
4. MUST: only two modules touch the address bar: `hooks/use-search-state.ts` (`window.history.replaceState`, shallow: no server round trip, the framework router follows it; `router.replace` there made five RSC requests, P32 N0) and `lib/external.ts` (`location.href = "mailto:…"`). `lib/storage.ts` owns `document.cookie` for the project. Anything else that names `window.location`, `history` or `document.cookie` is a defect.
5. MUST: the URL is the state of a screen. Subject = path (`/lisbon/drafts/42`), the view, query text, the batch and the opened session = query (`?filter=hold`, `?q=…`, `?batch=3`; Activity `?filter=` and `?run=3`). A key the parser does not know is dropped (rule 8): an old `/drafts?new=1` link opens Drafts, since nothing in the admin creates a batch (P48). A component keeps no second copy that Back, reload and a shared link cannot restore. Ephemeral UI (an expanded row) may stay local. The embedded terminal (P49) is not URL state, on purpose: Back must not open or close a terminal, and a link to a terminal means nothing off this machine (its sessions live in one local server). Its open state, width and tab are stored preferences (`state-and-data.md` rule 1); `Ctrl+`` toggles it through `use-hotkeys` (rule 12) as a modifier chord, the one chord that also fires while a field or the terminal has focus. The project a new terminal is for is the project of the address (`Place`, none on the projectless routes, where only Shell is offered); the browser sends that slug and a preset name, never a command or a path.
6. MUST: an unknown path is a real 404 (`not-found.tsx`); a non-numeric or zero id (`/drafts/abc`) and an extra segment render the explicit Not found state with a link to Drafts, never another screen. A bad id is streamed: its HTTP status is 200 with the Not found body and title (`notFound()` after streaming starts cannot change the status, research 19 section 5), so a test asserts the visible state and the title, never a status code for it. There is no `/clients` alias; `REDIRECTS` in `guards.ts` is empty and an entry needs a reason and a removal condition. The old hash addresses are gone, with no shim.
7. MUST: a row or card that navigates is an `AppLink` with a real `href`, not an `onClick` that sets the address.
8. MUST: search is parsed once, in `routes/search.ts` (plain functions over the enums of `@hub/config`, the same ones the API validates; a value outside its enum resets to the default). `URLSearchParams`, `params.get(` and `.searchParams` stay out of `features/`, `components/` and `hooks/`; the live query is read by `hooks/use-route.ts` and `hooks/use-project.ts` only (`useSearchParams`), and a page file reads `await props.searchParams` for its metadata.
9. MUST: a filter REPLACES the history entry (`useSearchState`), a subject PUSHES (`go(paths.drafts.item(id))`), so Back goes from a detail to its list and never steps through views. The default value drops its key from the address. The address names the card on screen (P53): on a pane wide enough for the split, Drafts opens its first row and, once the list has settled for the view and search, REPLACES a bare `/drafts` (or an id the list does not hold, said once in the pane) with `/drafts/<id>`; a narrow pane opens nothing and keeps `/drafts`. So a draft recorded at the top never swaps the card under the owner, and the focus (P51) names the same draft.
10. MUST: the project is a path segment, never a query (P48 point 15). With two or more projects every scoped address starts with it: `/lisbon/drafts/42`, `/lisbon/log?run=3`, `/lisbon/project`. With one project it is left out: `/drafts/42`, `/log`, `/project`; the whole admin is that project. The page files exist twice for that (`app/(shell)/drafts/…` and `app/(shell)/[project]/drafts/…`, the twin a one-line re-export), and `routes/table.ts` checks at compile time that every scoped row has its twin (`TWINS`). `Place {project, multi}` (`hooks/use-project.ts`, from the registry) is what `formatDest` needs to write an address; a component never builds the prefix. `canonicalAddress` in `routes/guards.ts` is the one normaliser, run once by `useEnsureAddress` in the shell frame with `replace`: a bare scoped path with two projects gets the remembered project (cookie `hub_project`, through `lib/storage.ts`) or the first one; a path-form address on a one-project instance folds back to the bare form; a dead slug goes to the remembered project, else the first (`pickProject`); `/` is Overview with two or more projects, Drafts with one; `/overview` with one project replaces to Drafts and the nav does not list it (`admin-principles.md` rule 7). The query-era addresses (`?project=lisbon`, until 2026-11-18) are read by `resolve.ts` and written in the path form by `canonicalAddress`, with a dated comment and `test/routes.test.ts` covering it; delete that branch when nothing links the old form. Two routes are about the instance, not a project (`PROJECTLESS`, the `scoped: false` rows): `/overview` (every project) and `/connections` (logins and tokens); they never carry a project and a project segment before them is Not found. A slug may not equal a top-level segment (`RESERVED_SEGMENTS`: the first segment of every table row, plus `health` and `api`). `src/proxy.ts` no longer redirects: the server cannot know the registry's count, and one normaliser is simpler than two.
11. MUST: the title comes from the route: each page file exports `generateMetadata` reading `pageTitle()` over `ROUTE_META` (`routes/meta.ts`); the breadcrumb reads the same table. Nothing writes `document.title`.
12. MUST: keys that navigate are derived from `SECTIONS` (`g o`, `g d`, `g a`, `g p`, `g c`) by `use-section-nav`; no key handler names a path. All key maps go through `use-hotkeys` (typing guard, modifier guard, remembered off switch).
13. MUST: the skip link is an anchor whose click handler focuses `#main` and prevents the default: a plain `#main` fragment would add a history entry and a hash to the address.
14. MUST: `src/routes/` imports no React, component, feature or hook, and no navigation library (`import type { Route } from "next"` is the one allowed `next` import). `next/*` navigation is for the modules in rule 3.
15. MUST: a page file is thin (at most 40 lines): await the params, give the title, render one feature. `routes/table.ts` is the one declaration of which pages exist (decisions 0021 and 0025): one `defineRoute(path, meta)` row per page, where `path` is the file-tree pattern (`typedRoutes` checks it, `/drafts/[id]` included) and `meta` says its section, whether it is scoped to a project, its title and crumb, and, for a section, its nav entry (`label`, `icon`, `order`, the `g` chord, and `when: "multi"` for a section only a several-project instance has). `SECTIONS`, the nav, the chords, `PAGE`, `PROJECTLESS`, `ROUTE_META` and `RouteId` derive from it; the shell reads the nav from it and lists nothing by hand. Why not `@djangocfg/nextjs`'s `defineRoute`: it brings server utilities and their dependencies (chalk, conf, consola, semver) into a local admin, it has no notion of a project placed in the path, and it does not tie a row to the file tree through `typedRoutes`; the local one is about forty lines with the same shape. A new page is: the folder under `src/app/(shell)/` (and its `[project]` twin when scoped), a `defineRoute` row, a `Dest` builder in `paths.ts`, an icon key in `nav-icon.tsx` when it is a section, and the `Resolved` variant with its `resolveRoute` and `destOf` cases. `tsc` forces each of those except the page file, which `test/route-files.test.ts` forces (a page without a row).
16. SHOULD: a new link, param or key uses `paths.*`, `useSearchState` and `SECTIONS`; it never adds a literal. Path routing is the design; do not add a second router or a `#/` form.
