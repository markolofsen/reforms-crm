# app

The TypeScript monorepo (`apps/`, `packages/`, the `hub` CLI).

**The rules in `app/@rules/` are binding. Always follow them, and read the relevant pages in full before you change code here.** Start with `app/@rules/README.md`: read the five pages of its reading order (architecture, structure, state, safety, verification), then the page that owns your task. Do not work from memory of a page: each rule is an invariant and the check that holds it (its Enforcement row), and its reason is the decision it cites.

- Editing `apps/admin` (Next.js 16 App Router, package `@hub/admin`): read the index, then every page it names for your task; `pnpm --filter @hub/admin check` runs the gates (`next typegen`, typecheck, eslint at zero problems, Vitest with the rules test) once, at the very end. Before touching navigation (a link, search param, key or title) read `app/@rules/routes-and-url-state.md`: destinations come from `src/routes/paths.ts` and render with `AppLink`, never a string; `next/link` and `next/navigation` are imported only in `src/app`, `src/hooks` and `components/app-link.tsx`. The admin talks to the Hono API over `/api` only: no `@hub/db`, no `"use server"`, no `NEXT_PUBLIC_*`. A client component's first render must not read the viewport, storage or the clock (`state-and-data.md` rule 11).
- A rule that no longer matches reality: change the page in the same change, with the reason. Never route around a rule silently.
- Layers: core never names a custom project, person or address (`@docs/LAYERS.md`).
- **Typecheck, lint, builds and tests only at the very end, when everything is written, one at a time** (owner, 2026-11-23). Never per edit, per slice, per phase or before a commit, not even `tsc` on one touched package; a commit in between may not compile. `pnpm --filter @hub/admin check` and the rest of the ladder run once, in the final gate (`app/@rules/verification.md` rule 2).
- **At most two local servers at once** (owner, 2026-11-23): the API, a Next app, Storybook and a docs site each count as one. Check what listens first (`lsof -nP -iTCP -sTCP:LISTEN`), stop one of yours before starting another, and stop yours when done (`app/@rules/verification.md` rule 2a).
- Paths: every location comes from `@hub/config/paths` (`hubPaths`); `HUB_HOME` is the instance root and is required (core code and `app/projects/_template` are the only things this repo holds). Gate: `apps/installer/test/home-seams.test.ts`; rules README 8.
- **Work in your own worktree, never in this checkout** (owner's instance, 2026-11-25). hub-saas runs this checkout live through the `core` dev link: its server, admin build, `hub guard` hooks and the dock's `hub mcp` all load these sources. A half-written file here breaks the owner's dock at once (that happened three times on 2026-11-25: a migration file made the MCP refuse `db_behind`, a contract change without `pnpm generate` failed the admin build, and a duplicate export crashed every guard hook). So: `git worktree add ../reforms-hub-<track> -b <track>-work`, commit there, and report "ready at <commit>; touches mcp/: yes/no; migration: yes/no". The coordinator fast-forwards `main` and restarts saas together, while the dock is idle. A commit offered for `main` must compile (admin and server), which is the only exception to "no tsc before a commit".
- **Check the open pull requests when you start core work** (owner, 2026-11-25): `gh pr list --repo markolofsen/reforms-hub --state open`. Outside contributions are never merged as they are. Read every changed line for security first: data sent anywhere but the named service, new or changed dependencies and lockfile entries, postinstall scripts, weakened admin gates or caching, secrets in logs, and obfuscated code. Then take what is useful into a plan (`@dev/planned/`), re-implemented on current `main` by our writer, with the PR credited in the commit and the PR answered. Report every PR you find, even one you would reject.
